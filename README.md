# Agentic · 会从经历中学习的分盘助手

给它盘数、单盘容量和文件大小，Agentic 会尝试把文件完整装下。每份答案都能逐盘验算。更难的问题是，遇到一次失败，能不能学出一条在下次值得执行的规则？这个项目把失败、实验、代价和最终决定都留在本机。

## 启动与演示

在项目目录用 Python 3.9 或更高版本运行，只需标准库。

```sh
./agentic
```

在交互窗口输入 `research` 开启配方研究，随后输入 `10 2 4 4 6 6`。前两项是容量和盘数，其余为文件大小。`q` 退出，用同一命令重启会读回 `state/live/`。开启研究之后，遇到新的未解清单，Agentic 会自动决定下一轮尝试。

**复跑最新一轮配对实验**，从第 10 条记录的 v1 开始，用一个命令观察自主学习和重启验收。

```sh
python3 -B scripts/pair_round.py
```

面对原来装不下的 40 份清单，Agentic 学会了在每个文件都能找到互补文件时先按降序放置。40 份全部装完，其中 34 份未抽入练习。它在独立留出多解 6 份，回归保住 12 个旧成功，两组合计成本为原来的 1.324 倍，自己保留了 v2。重启后它装完了事前封存的 6 盘严格配对题。同批另 12 个带独占盘、混合或近似配对的可行输入仍未解。演示最后打印继续使用该记忆的命令。在终端给这条启动命令追加 `research --batch 批次.json`，就能用自己的清单数组再试一轮。[本轮原始对照、成本和重启证据](evidence/pairs/report.md)

**从空白状态复跑第 1～9 轮**，使用下面的命令。

```sh
./demo-research
```

它在新目录从空白记忆开始，依次提交八份已约定的用户清单，每次调用都是新进程。首轮提名在留出多解 11 份，却因成本达到 2.37 倍被放弃。到记录 #9，它学出了一条可执行规则：盘数至多为 4 时，先约分和剥离独占盘文件，再按大小排序，允许局部搬移或交换。独立留出从 21/64 到 24/64，回归仍为 11/18，合计操作为 1.52 倍，Agentic 自己保留了它。

重启后用只读 `probe` 看两份新任务。事前单独封存的 8 盘配对题触发了规则的跳过条件，直接作答仍然失败。改用 `solve` 时，现役版本能从本轮练习取回并复核八个盘的装法。另一批独立封存的 72 份清单中，实际活动策略比自己的 v0 多解 12 份。演示展示按文件顺序出现的第一份新增成功，9 个文件正好装满三个容量为 503 的盘。成功与失败的计数包括全部输入。[实验记录与逐例证据](evidence/pilot/report.md)

## 继续给它任务

演示最后会打印一条打开该次新记忆的命令。直接粘贴即可继续输入清单。新克隆只包含代码、公开的实验记录和验收用的参考结果。要查看发布时的固定现场，先运行下列第一条命令。它从六条早期记录和示例清单重建 SQLite；如果目录已有现场，会保留已有内容。

```sh
python3 -B scripts/restore_demo_states.py
S=state/pilot/round-01/stream
./agentic --state "$S" show 9
./agentic --state "$S" explain 9
./agentic --state "$S" probe examples/pilot-independent.json
```

`show 9 --json` 包含每次试验的父配方、选择原因、成败、操作成本、逐例留出和最终决定。`explain` 在练习或指定清单上移除步骤、颠倒顺序或换回旧策略，寻找可复算的差异。`probe` 仅读取策略。`solve 清单.json` 会作答并在需要时继续研究。`rollback` 在该状态中恢复上一份活动策略，试验记忆和记录仍可查阅。自己的 JSON 可写成 `{"capacity":10,"bins":2,"items":[4,4,6,6]}`，输出装法使用原文件下标。

## 开发者提供什么，运行时学什么

开发者提供两种可逆的输入变换、已有分盘技能、可测输入特征、预算与验收规则。Agentic 选择父配方和修改方向，试运行后用收益差异拟合使用条件，并把结果写进 SQLite。每轮默认最多 128 次共享基线与候选评估，只把一份提名送入独立验收。至少多解 3 份、零丢失、成本不超过 2.25 倍才可保留；正式规则还要求足够多的旧成功和留出样本。研究经历与活动策略可以独立保存。[正式约定](evidence/pilot/protocol.md)

参考 AgentPilot 的两个设计是隔离未揭示的证据，以及用既往评估来选择下一次尝试。这里的研究对象是能执行、能逐项撤销验证的分盘配方。推理、存储和验收均在本机完成。[AgentPilot 的证据状态](https://github.com/HKUDS/AgentPilot/blob/e5a81e7635009869d34dde8fbfd045d191296f3f/agentpilot/src/agentpilot/search/state.py) · [AgentPilot 的反馈更新](https://github.com/HKUDS/AgentPilot/blob/e5a81e7635009869d34dde8fbfd045d191296f3f/agentpilot/src/agentpilot/policy/ucb/updater.py)

目前支持 1～16 个等容量盘、最多 64 个文件。搜索覆盖有限，超预算的未解清单仍可能有解。独立对照中，按实际落盘方式重启的自适应搜索在 576 份检验输入上解出 452 份，均匀搜索解出 465 份。旧报告的 462 份对应保留内存访问顺序的实验。操作数是确定性的求解工作量指标，真实用时单列。早期演示仍可用 `./agentic demo`、`./agentic demo triples`、`./agentic demo mixed` 复跑。[初版演示](evidence/demo.txt) · [三件配平](evidence/triples/report.md) · [四份混合清单](evidence/mixed/report.md) · [文件校验摘要](evidence/sha256.txt)

## 核验现役版本和已发布实验

```sh
python3 -B scripts/verify.py --full
```

去掉 `--full` 可快速检查状态读写、答案检索、跨进程学习和互补条件。完整模式还会核对四组历史结果、两种记忆顺序的等预算对照、70 份配对题、第 11 轮正式决定和封存验收。历史复跑从附带的固定源码恢复环境，源码导出目录也可以离线核验。同一清单曾找到的合法装法按原文件顺序重新核验。运行 `solve` 可交付当次装法，只有通过正式门槛的配方才会在新任务上自动启用。[上一轮深度评估与边界](evidence/review/report.md)
